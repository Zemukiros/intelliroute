# IntelliRoute — Development Log: August 1, 2026 (Step 1)

## What happened today

IntelliRoute went from nothing to a working, tested, CI-verified application published on GitHub. The project was built as a brand-new standalone monorepo with its own git history — the old Town Graph Network coursework was left untouched and served only as historical inspiration.

The result is the platform's first complete vertical slice: a user can open the web app, pick two towns, click Calculate Route, and get back the shortest path computed by a real Dijkstra implementation running inside a Spring Boot API — including the actual measured execution time of the algorithm.

Repository: https://github.com/Zemukiros/intelliroute

## What was implemented

### Backend — Java 21, Spring Boot 3.4, Maven (`services/api`)

A layered routing engine with clean separation between domain, algorithm, service, and web layers:

- **Domain model** — immutable `Graph`, `Node`, and `Edge` types built through a validating builder. Invalid input (duplicate nodes, unknown endpoints, negative weights, self-loops) is rejected at construction, and immutability makes the shared network safe for concurrent requests without locking.
- **Dijkstra's algorithm** — a stateless `DijkstraPathFinder` using a binary-heap priority queue with lazy deletion and early termination when the destination is settled. Complexity O((V+E) log V). It reports how many nodes it visited, so the algorithm's behavior is observable from the UI.
- **REST API** — `POST /api/routes/calculate` accepts an origin and destination, validates them, and returns the path, total distance, visited-node count, and execution time measured per request with `System.nanoTime()` (never hard-coded). `GET /api/routes/network` serves the graph for visualization.
- **Error handling** — one consistent JSON error shape for everything: 400 for validation problems, 404 for unknown nodes, 422 for reachable-nodes-but-no-path. The sample network includes a deliberately disconnected island town ("Juniper Isle") so the unreachable case is demonstrable end to end.
- **Sample network** — 10 towns and 15 two-way weighted roads.

### Frontend — Next.js 15, TypeScript, Tailwind CSS (`apps/web`)

An interactive route planner: origin and destination dropdowns, a Calculate Route button, a results panel (path, distance, visited nodes, engine time), and an SVG visualization of the whole network that highlights the calculated route, origin, and destination. The graph renders from data served by the API — no map SDKs, no API keys, no paid services. If the backend is offline, the UI shows a recovery card with the exact command to start it instead of breaking.

### AI service scaffold — Python, FastAPI (`services/ai-service`)

The future natural-language route-preference feature ("avoid highways", "prefer the safest route") got its service boundary today, at zero cost: a `RouteRankingProvider` interface with a deterministic mock implementation behind `/health` and `/rank` endpoints. A real AI provider can be swapped in later without changing the contract. No paid AI API is called anywhere.

### Infrastructure and quality

- **Testing** — 24 JUnit tests: algorithm unit tests (correct paths, unreachable destinations, invalid nodes, edge cases), domain invariant tests, and full-stack MockMvc API tests covering every success and error status.
- **CI pipeline** — GitHub Actions workflow with three jobs: full Maven build and test plus a live smoke test that boots the real jar and hits it with HTTP requests; frontend lint and production build; AI-service sanity check.
- **Docker** — Dockerfiles for all three services and a `docker-compose.yml` that runs the whole stack locally.
- **Documentation** — README, ARCHITECTURE.md, API.md, ROADMAP.md, TECHNICAL_DECISIONS.md (7 recorded decisions with rationale), and RESUME_EVIDENCE.md (the verified-claims tracker).
- **Hygiene** — `.gitignore` covering secrets, env files, build output, and dependencies; `.env.example` for configuration; secret scan before commit came back clean.

## Published and run end to end

The repository was pushed to GitHub (github.com/Zemukiros/intelliroute) using GitHub CLI with browser authentication, and CI went green on the very first run. The local development environment was then set up from scratch on Windows: Temurin JDK 21 via winget, Apache Maven 3.9.16 (direct install after the winget package ID failed to resolve), with Node.js already present. Both services were started locally — `mvn spring-boot:run` for the API and `npm run dev` for the frontend — and the application was verified working in the browser at localhost:3000: the road network rendered live from the API's network endpoint, with origin/destination selection and the intentionally disconnected Juniper Isle visible, confirming the frontend-to-backend connection on real hardware. VS Code was chosen as the IDE for Java development going forward (Extension Pack for Java + Spring Boot Extension Pack).

## Notable engineering decision

The cloud build environment blocked Maven Central downloads, so the project adopted a professional workaround: the algorithm core was kept deliberately framework-free (making it verifiable with the JDK alone), and GitHub Actions was designated the authoritative build-and-test environment. The first CI run on push confirmed everything green. Recorded as TD-007 in TECHNICAL_DECISIONS.md.
